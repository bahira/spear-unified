# SPEAR Unified — audit roadmap (2026-11-19)

This plan is based on a static inspection of main, repository instructions, issues and draft PR descriptions. It does not claim independent test execution or validated application-level speedups.

## Milestones

- **M1 — Validation et benchmarks fiables**: secure AST compilation, validate numerical behavior, review draft PRs and establish merge gates.
- **M2 — Compromis précision et vitesse**: reproducible end-to-end benchmarks with explicit error budgets and strong baselines.
- **M3 — Backends et outils optionnels**: integrate a native/WASM backend or external adapters only after representative evidence and security review.

## Evidence and limitations

- Main includes pinned SiLU/GELU formula records, a Python AST compiler, bounded discovery, tests, reports, and a local dashboard.
- `compile_tree` currently has no explicit maximum tree depth or node count in its source; issue #12 tracks validation and regression coverage.
- The discovery adapter limits budgets and subprocess time, but a finite holdout is not a continuous-domain accuracy certificate.
- Draft PR descriptions contain historical test and benchmark results; these are **not** independent results from this audit.
- Python-to-C boundary costs can erase microkernel gains. Do not select or promote a backend automatically.
- Browser and LLM adapters are explicitly unavailable.
- Preserve `AGENTS.md`, `GOAL.md`, Triple Helix constraints, and no heavyweight installations by default.

## Verification commands (to run on an actual checkout)

```sh
python -m unittest discover -s tests -v
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test tests/benchmark.test.mjs
python bench.py
git diff --check
```

Record exact branch, commit SHA, environment, durations and raw results for each execution. A passing source inspection is not equivalent to executing these commands.

## Change policy

Create focused branches and PRs, require passing checks before merge, keep adaptation disabled pending #6, and avoid claiming production readiness before a representative client workload passes end-to-end.
